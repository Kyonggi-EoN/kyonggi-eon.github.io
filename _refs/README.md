# 디자인 레퍼런스

사이트 디자인을 고칠 때 근거로 삼는 레퍼런스 모음입니다. `_`로 시작하는 폴더라 사이트 빌드에는 들어가지 않습니다.

레퍼런스 하나 = 폴더 하나입니다.

```
_refs/
  2026-11-16-<사이트>-<이름>/
    shot.png   해당 부분 스크린샷 (주변 여백 포함)
    ref.md     머리말 + 메모 + 자동 수집 값
  DESIGN.md    레퍼런스가 쌓이면 원칙으로 압축 (아직 없음)
  tools/       캡처 스크립트
```

## 하나 추가하기

처음 한 번만 설치합니다.

```bash
cd _refs/tools && npm install
```

저장소 루트에서 실행합니다.

```bash
node _refs/tools/capture.mjs <url> "<selector>" [이름] [--avoid] [--width 390]
```

- `selector`: DevTools에서 요소를 우클릭한 뒤 Copy → Copy selector로 복사한 값을 그대로 넣어도 됩니다. Playwright 문법(`text=동아리 소개`, `.card >> nth=2`)도 쓸 수 있습니다.
- `--avoid`: 피하고 싶은 것(안티 레퍼런스)으로 저장합니다.
- `--width 390`: 모바일 폭으로 찍습니다.
- 시스템 Chrome을 씁니다. 다른 브라우저를 쓰려면 `CHROME=/경로 node …`처럼 경로를 지정하세요.

실행하면 `ref.md`의 메모 칸만 채우면 됩니다. Claude에게 URL, selector, 좋은(싫은) 이유를 주면 실행부터 메모 정리까지 대신 해 줍니다.

로그인이 필요하거나 봇을 막아서 안 열리는 사이트는 Chrome DevTools에서 `Ctrl+Shift+P` → "Capture node screenshot"으로 직접 찍습니다. 그 파일을 새 폴더에 `shot.png`로 넣고, 다른 레퍼런스의 `ref.md`를 복사해서 머리말과 메모만 고칩니다.

## 메모 쓰는 법

- **형용사 말고 속성으로 씁니다.** "깔끔함"(✗) 대신 "카드에 테두리·그림자 없이 48px 여백으로만 구분"(✓)처럼 씁니다. 이렇게 써야 그대로 옮길 수 있습니다.
- **레퍼런스 하나에는 포인트 하나만 담습니다.** 사이트가 통째로 좋으면 좋은 부분마다 따로 찍으세요.
- **싫은 것도 모읍니다(`--avoid`).** "이렇게는 하지 않는다"가 방향을 더 빨리 정해 줍니다.
- 머리말
  - `part`: hero · header · nav · card · list · article · footer · page
  - `axis`: type(글꼴·크기) · color · layout(배치) · density(여백·밀도) · motion · image · copy(문구)

## 어디서 찾나

웹사이트만 보면 결국 비슷한 사이트로 수렴합니다. 전자공학 쪽 실물 자료도 함께 보세요. 데이터시트의 표와 주석 글씨, 회로도·PCB 실크스크린, KLayout 레이어 색, 오실로스코프 화면, 공학 도면 표제란 같은 것들입니다.

## 정리

`like`가 10~15개쯤 쌓이면 공통점을 뽑아 `DESIGN.md`(지킬 원칙 5~7줄 + 피할 것 목록)로 압축합니다. 그 뒤 사이트를 고칠 때는 `DESIGN.md`를 기준으로 삼습니다.
